## 개요

**Pickle**은 부산대 학생에게 가상 서버(VM)와 교내 LLM API를 나눠 주는 교내 클라우드 플랫폼입니다. 승인받은 학생은 VM을 받아 SSH와 도메인 기반 HTTPS로 서비스를 올리고, 교내 장비에서 돌리는 학교 모델(pickle-general)을 사용 금액 없이 쓸 수 있습니다. 학교 모델은 NVIDIA DGX Spark에서 vLLM으로 서빙하고, 필요하면 한도 안에서 유료 외부 모델도 같은 키로 씁니다. 학과 같은 다른 기관도 따로 등록해 쓸 수 있는 구조입니다.

- **서비스 주소**: [pickle.pusan.ac.kr](https://pickle.pusan.ac.kr)
- **역할**: AI융합교육원 기관 관리자(운영). 플랫폼 개발은 개발팀(PNUops)이 했습니다.
- **수업 사용**: 수업에서 나온 AI 요청 3,095건 가운데 토큰 기준 85.3%를 교내 모델이 처리했습니다(개발팀 집계).

## 내가 맡은 일

Pickle의 코드는 내가 쓰지 않았습니다. 내가 하는 일은 이 플랫폼이 교육원 수업과 학생에게 실제로 쓰이게 만드는 운영입니다.

- **승인 기준 정리**: VM과 LLM 키 신청이 계속 들어오는데, 승인 담당자는 하드웨어 한계를 모른 채 판단하고 있었습니다. VM은 CPU가 먼저 바닥나니 남은 vCPU 합계 안에서, LLM 키는 키 개수보다 같은 순간 몇 명이 쓰는지가 중요하다는 기준으로 승인 가이드를 만들었습니다. 학교 모델은 동시에 처리하는 요청 수가 정해져 있어서, 한계를 넘으면 "안 됨"이 아니라 "느려짐"으로 나타납니다.
- **개발팀에 기능 요청**: 승인 화면의 과다 할당 경고가 실제 배치 한도보다 훨씬 늦게 뜨고, 노드 메모리 값이 등록할 때 잰 값에 고정돼 증설 뒤에도 바뀌지 않는 점을 찾아, 남은 자원 표시와 묶음 신청 배치 가능 여부 표시를 요청했습니다.
- **학생 연결 지원**: 수업에서 학생 30명 가운데 일부가 API 키 연결에 실패했습니다. 실패 사례를 원인별로 나눠 연결 매뉴얼을 만들고, 교내 유선망에서 특정 주소의 443 포트만 막히는 경로 문제는 원인을 짚어 개발팀에 전달했습니다.
- **장애 대응**: 서버 두 대의 메모리를 증설하고 재부팅하자 가상 서버가 하나도 켜지지 않아 서비스가 약 6시간 30분 멈췄습니다. 부팅 때 도는 안전 검사가 서로의 BMC에 연결된 구조에서 한쪽 BMC와 통신하지 못해 실패한 것이었고, 링크 상태를 3초 간격으로 기록하며 가설을 좁혔고, BIOS에서 BMC 포트 모드를 다시 적용하자 통신이 돌아왔습니다. 원인을 하나로 확정하지는 못했고, 그 과정은 따로 글로 정리할 예정입니다.
